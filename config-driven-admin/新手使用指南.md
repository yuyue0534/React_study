# 配置驱动后台架构 · 新手使用指南

这份指南面向第一次接触这套 DSL 的开发者，目标是让你在半小时内跑起来 demo，
并且能照葫芦画瓢加一个自己的业务模块。更完整的字段参考见《配置驱动架构规格书》。

## 一、这套东西解决什么问题

后台管理系统里大部分页面长得都差不多：搜索栏 + 表格 + 增删改查按钮，区别只在
字段、接口和少量交互上。与其每个模块手写一遍页面，不如把这套结构抽象成一份
JSON 配置，写一个解析器去拼装。

一句话总结整条链路：

```
一份 DSL 配置 (menu 数组)  →  解析器读取  →  自动拼装菜单与组件  →  完整业务模块
```

改页面只需要改配置，不用碰组件代码；新增模块基本等于新增一份配置文件。

## 二、5 分钟跑起来

```bash
unzip config-driven-admin.zip
cd config-driven-admin
npm install
npm run dev
```

打开终端提示的本地地址，你会看到两个 tab：

- **核心链路 demo** —— 左侧菜单栏由配置自动生成，点开任意模块，右侧能展开"驱动
  配置"面板，看到当前页面对应的原始 JSON。改这份配置，页面会跟着变。
- **project 继承 model** —— 演示同一套模板怎么派生出多个项目（拼多多/京东/淘宝）。

想单独验证 `project 继承 model` 的合并逻辑，不用起浏览器：

```bash
npm run test:merge
```

## 三、核心概念，先认识这四个词

| 概念 | 是什么 |
|---|---|
| `menu` | 顶层菜单数组，可以无限嵌套，是整个系统的骨架 |
| `menuType` | 这个节点是能点开的页面（`module`）还是只用来分组的目录（`group`） |
| `moduleType` | 当 `menuType: 'module'` 时，决定这个页面用哪套模板渲染：`schema` / `iframe` / `custom` / `slider` |
| `schemaConfig` | 最核心的配置，写好它就能自动拼出一个标准的增删改查页面 |

## 四、动手加一个模块：以"优惠券管理"为例

假设你要在现有系统里加一个优惠券管理页面，字段有：优惠券ID、名称、折扣、状态。

### 第 1 步：在 `menu` 数组里加一个新节点

```javascript
{
  key: 'coupon',            // 唯一标识，路由和数据关联都靠它
  name: '优惠券管理',        // 菜单里显示的名字
  menuType: 'module',       // 这是个可点开的页面
  moduleType: 'schema',     // 用增删改查主力模板渲染
  schemaConfig: {
    // 下面几步继续填
  },
}
```

### 第 2 步：填 `api`

```javascript
schemaConfig: {
  api: '/api/proj/coupon',
  // ...
}
```

### 第 3 步：定义字段（`schema.properties`）

每个字段身上按需要挂三种 option：`tableOption`（表格里怎么显示）、
`searchOption`（搜索栏用什么组件）、`formOption`（新增/编辑表单里怎么录入）。
**只有挂了对应 option 的字段才会出现在那个视图里**，不挂就不显示，这是最常
用来控制"这个字段要不要出现在搜索栏/表格里"的方式。

```javascript
schema: {
  type: 'object',
  properties: {
    coupon_id: {
      type: 'string',
      label: '优惠券ID',
      tableOption: { width: 140 },
      // 没配 searchOption / formOption -> 不出现在搜索栏和表单里，只在表格展示
    },
    title: {
      type: 'string',
      label: '名称',
      tableOption: { width: 180 },
      searchOption: { comType: 'input', placeholder: '搜索名称' },
      formOption: { comType: 'input', required: true },
    },
    discount: {
      type: 'number',
      label: '折扣',
      tableOption: { width: 100 },
      formOption: { comType: 'input' },
    },
    status: {
      type: 'string',
      label: '状态',
      tableOption: { width: 100 },
      searchOption: {
        comType: 'select',
        enumList: [
          { label: '全部', value: '' },
          { label: '生效中', value: '生效中' },
          { label: '已过期', value: '已过期' },
        ],
      },
    },
  },
}
```

### 第 4 步：配按钮

```javascript
tableConfig: {
  headerButtons: [
    { label: '新增优惠券', eventKey: 'showComponent', type: 'primary' },
  ],
  rowButtons: [
    { label: '修改', eventKey: 'showComponent', type: 'warning' },
    {
      label: '删除',
      eventKey: 'remove',
      type: 'danger',
      // schema::coupon_id 表示"从当前行数据里取 coupon_id 字段"
      eventOption: { params: { coupon_id: 'schema::coupon_id' } },
    },
  ],
}
```

写完这四步，一个完整的优惠券管理页面就有了——不用写任何组件代码。

## 五、moduleType 怎么选

| 你想要的效果 | 选哪个 `moduleType` |
|---|---|
| 标准的搜索+表格+增删改查 | `schema` |
| 嵌入一个外部系统/页面 | `iframe`，配 `iframeConfig.path` |
| 完全自定义、DSL 管不了的页面 | `custom`，配 `customConfig.path` 指向自定义路由 |
| 带侧边二级菜单的复合页面（里面还能再塞 schema/iframe/custom） | `slider`，配 `sliderConfig.menu` |

一个经验法则：**先看能不能用 `schema` 解决**，只有真正做不到标准增删改查形态的
页面（比如需要嵌入历史系统、或者交互逻辑特别定制）才考虑 `iframe`/`custom`。

## 六、常见问题

**Q: 字段配了 `tableOption` 但表格里没显示？**
检查 key 名有没有拼错，`buildDtoSchema` 是按 `${comName}Option` 精确匹配的，
比如表格用的是 `tableOption`，大小写和拼写要完全对上。

**Q: 点删除按钮报"未注册的 eventKey"？**
说明 `eventKey` 写了一个系统里没注册过的值。内置的只有 `showComponent` 和
`remove`，新增动作要先去事件注册表里加一条处理函数，再在配置里引用。

**Q: 想给多个项目复用同一套配置，但个别字段要改？**
用 `project 继承 model` 机制：写一个 model 模板，各项目的 project 文件只写
"要覆盖的那一小部分"，其余自动继承。具体规则见规格书里的"合并规则"一节。

**Q: 新增按钮点了之后什么反应都没有？**
先看 `eventKey` 有没有写对；如果是自定义动作，确认对应的处理函数确实往
`eventHandlers` 注册表里注册过。

## 七、下一步

- 想了解每个字段完整的可选值、类型约束 → 看《配置驱动架构规格书》
- 想扩展新的 `moduleType`（比如加一个看板视图）→ 往 `moduleRegistry` 里注册一个新组件，不用改解析器
- 想加新的 `eventKey`（比如导出、审批）→ 往 `eventHandlers` 里注册一个新的处理函数
